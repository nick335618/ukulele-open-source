# 当前交付 App v3.12.3 / code 57（相册识谱多格式 + 搜索短片段过滤）

## 本版变化（v3.12.3）

针对实测反馈「只能识别简谱 / 搜送别只有 4 秒」：

- **相册识谱先分类再分流**：数字简谱 → JianpuParser；四线 TAB → 新增列级解析（同列多弦保留为和弦/双音同时发声）；弹唱谱/和弦图 → 视觉只识别和弦进行+节奏型，App 用内置 `fun/ChordLibrary` 确定性合成扫弦；五线谱 → 转写单声部 ABC → AbcParser 确定性解析；转写不了会给明确提示。
- **质量门槛**：相册 TAB/五线谱结果须 ≥12 音且 ≥8 秒，否则严格重试/报错，不再把片段当完整曲谱。
- **搜索结果过滤**：ABC/TAB 候选须 ≥12 音且 ≥8 秒，短片在 `skippedSources` 记录原因；无结果给可执行建议。
- **别名改进**：送别→Dreaming of Home and Mother / Song of Farewell；茉莉花、月亮代表我的心等中文老歌示例；通用词不再参与相关性匹配。
- 用户样张实测：送别弹唱谱 256 note-on/约 32 秒（此前 16 音/4 秒）；曹操 1472 note-on/约 2.5 分钟；送别搜索 4 个候选（58 秒级），无 4 秒片段。
- 构建：v3.12.3 / code 57，APK 1,712,468 B，SHA-256
  `7A6F10BFD84415EC46148D24B4041B3BBEC9840FE823F7E2CDD7BDFE43DCB7A4`，`classes.dex` MD5
  `3ED6329C0DE82AB8CCD4B54422142D72`；权限不变（基线 7 + `RECORD_AUDIO`），无新第三方依赖。
- 限制：密集 TAB 逐音准确率仍依赖照片清晰度，AI 转录必须校对；弹唱谱分类可能仍走 TAB 分支；和弦库仅 18 个常用和弦；五线谱暂无真实样张；真机本轮 adb 断开，未做走查。

# 历史交付：App v3.12.2 / code 56（AI 曲谱助手：多来源搜索 + 12 秒试听选择）

## 本版变化（v3.12.2）

针对「导入乐谱不能只搜一个网站、搜不到怎么办、重名版本要能试听再选」：

### 一、多来源搜索
「搜曲谱（多来源）」会同时尝试多类来源：

| 来源类型 | 站点/方式 | 解析 |
| --- | --- | --- |
| ABC 谱库 | abcnotation.com、thesession.org、mutopiaproject.org、tunearch.org | Search 正文优先 → 页面兜底 → **AbcParser 本机解析**（版权页/无音符自动跳过） |
| MIDI 站 | bitmidi.com（页面 HTML 里的 `/uploads/*.mid` 直链）、midiworld / freemidi / hamienet / mfiles / mutopia / midishow / 8notes 等（搜索+页面链接） | WebDownloader 下载 → `MThd` 校验 → **App 既有 MIDI 解析器** |
| Ukulele 谱站 | ukutabs.com、ukulele-tabs.com、ukulele-facile.com | 若正文含真实四行品格 tab → **UkuleleTabParser 本机解析**；只有和弦/图片 → 记为「未采用」，**绝不编造** |

- 中文歌名先由模型生成 1–3 个英文别名，别名优先搜索、原名兜底（英文谱库命中率更高）。
- 单源失败不阻塞；总预算约 90 秒；有足够候选会提前结束。

### 二、候选列表 + 12 秒试听
- 最多返回 **6 个候选**，每个显示：曲名、来源站点、绿「确定性」/黄「AI 转录需校对」徽标、音数/时长（MIDI 显示文件大小）、可点击来源。
- 每个候选可「试听」——用 App 内置合成器播放 **12 秒**（文本候选走 SongTimeline→PreviewPcm；MIDI 候选保留原始编配音高），同一时间只播一条，再点「停止」/切换/关闭都会停。
- 点「用这个」进入原有明细区：可编辑转录、重新解析文本、MIDI 直接导入；可「重新选」回候选列表。
- 排序优先简单主旋律版本（ABC > TAB > MIDI，同类内音数少者优先），重名多版本都保留给用户试听决定。

### 三、搜不到时怎么办
0 候选时不只报错，而是显示诊断卡：
- **已尝试来源** 与 **跳过原因**（如「ukutabs.com：仅和弦/图片，未找到可解析的四行 tab」）；
- 四个可执行入口：**换英文名再搜** / **相册识谱** / **粘贴简谱（含 4 行 TAB）** / **粘贴网页链接**；
- 再试一次。

### 四、验证
- JVM：UkuleleTabParser/MidiUrlFinder/候选排序/旧 API 兼容 **62/62 PASS**。
- 真实 API：5 首中文歌 **5/5 首返回多来源候选**（每首 5–6 条、2–4 个站点）；小星星首候选 thesession 42 音、另含 abcnotation 与 bitmidi MIDI；bitmidi 真实「HTML→uploads/107593.mid→下载 2844B→MThd=true」；ukutabs 仅和弦 → 明确 skipped 不编造。
- 构建：v3.12.2 / code 56，APK 1,704,276 B，SHA-256
  `BB93E14E7198DB00646AE4122B890BBC1530EE2D4EF6554AC15BF8938BA67D2E`，`classes.dex` MD5
  `6DD633AFCB99C598D12E82866AEB3421`；权限与上一版相同（基线 7 + `RECORD_AUDIO`）。
- 限制：站点可达性/内容会变（部分 MIDI 页 Fetch 504、部分站点限流）；TAB/MIDI 不是每首歌都有；排序只是启发式，音乐正确性仍需试听+校对；识别不到时请按诊断建议换方式。

## 本版新增与变化（v3.12.1）

### 一、AI 曲谱助手 2.0：从「让模型编事件」改为「确定性解析」
旧版把搜到的网页正文交给模型直接生成演奏事件，中文曲谱搜索结果多是知乎/图片站/无关页，
模型只能凭空编造——这是「不靠谱」的根因。新版把职责拆开：**AI 只负责搜索/识别，App 负责确定性转换**。

| 输入 | 新流程 | 结果可信度 |
| --- | --- | --- |
| 搜曲谱（默认） | 中文歌名先用模型转 1–3 个英文别名 → DeepSeek Search 搜 `abcnotation.com` ABC 谱 → Fetch 页面 → **AbcParser 本机解析** → ScoreArranger 编配 | 绿色「确定性解析」 |
| MIDI 兜底 | 搜 `<歌名> midi` → 抓页面中的 `.mid` 直链 → WebDownloader 下载（仅 https/4MB/MThd 校验）→ 交给 App **既有 MIDI 解析器** | 绿色「确定性解析」 |
| 粘贴简谱/ABC | JianpuParser / AbcParser 本机解析（AI 只在内容不规范时把它转写成「规范简谱文本」） | 规则解析=绿；AI 转写=黄「请校对」 |
| 相册识谱 | `deepseek-flash` 只输出 `{"title","bpm","jianpu"}`，再由 **JianpuParser 本机解析** | 黄色「AI 转录，请校对」 |
| 网页链接 | Fetch 正文 → 同上（ABC/简谱规则优先） | 视来源而定 |

- 结果区新增**可信度徽标 + 可点击来源 URL**；转录/简谱文本可编辑后「重新解析文本」（改对后会变绿）。
- MIDI 草稿直接显示「MIDI 已下载，用内置解析器导入」，不展示自由生成的事件。
- 错误提示给可执行建议（换歌名 / 改用相册 / 粘贴简谱示例）。
- 实测（真实 API）：小星星 42 音、欢乐颂 62 音、生日快乐 50 音、两只老虎 36 音、铃儿响叮当 78 音，
  **ABC 确定性命中 5/5**（0.8–1.9s，全部来自 abcnotation.com；不同 ABC 版本音数可能略有差异）；
  小星星解析结果与内置 `assets/songs/twinkle_twinkle.txt` 逐音一致（ABC 高八度 -12 后 42/42 音高、时值比例完全一致）。
- 限制：ABC 以单声部传统/公版旋律为主，流行歌可能找不到；MIDI 兜底受第三方站点可达性影响；
  识图/文本转写本质仍有模型误差，必须校对转录后再导入。

## 本版新增与变化（v3.12.0）

### 一、AI 配置入口（新手友好）
- 入口：**设置 → AI 与音乐搭子 → 配置 AI / API Key**；乐趣页与聊天弹窗也会在未配置时自动引导。
- 三种通道：
  1. **官方通道**：输入口令 `gowin` 即可使用开发者预置的 Key（构建时注入，见下方构建说明）；
  2. **我的 API Key**：粘贴个人 DeepSeek Key（`sk-...`），支持「获取 API Key」跳转、显示/隐藏、格式校验、
     「测试连接」与模型选择（`deepseek-flash` 推荐：快、便宜、支持看图；`deepseek-v4-pro`：更强的思考能力）；
  3. **关闭 AI**：不联网、不请求任何权限。
- 个人 Key 使用 **Android Keystore AES-GCM 加密**后保存在本机；请求直接发往 `https://api.deepseek.com`，
  不经过第三方服务器。语音对话首次使用时会申请麦克风权限，拒绝后仍可文字聊天。

### 二、AI 曲谱助手（曲库页 →「AI 曲谱助手」）
- 四种导入方式：
  - **搜曲谱**：输入歌名 → DeepSeek Search 接口搜索 → Fetch 抓取网页正文 → 模型转换成弦位事件；
  - **网页链接**：粘贴任意曲谱/简谱网页 URL，抓取正文后转换；
  - **粘贴文本**：直接粘贴简谱、歌词、TAB 或文字描述；
  - **相册识图**：选一张谱面照片，用 `deepseek-flash` 的图像理解识别简谱/TAB/和弦图后转换。
- 转换结果先显示「转录文本 + 事件预览 + 可演奏性摘要」，可编辑/重新生成；只有通过 App 既有
  `normalizeTextSong + SongTimeline.parse` 校验的事件才允许「导入到曲库」，导入后走原有选曲/试听/上传流程。
- 原有的「在线下载 / 选择本地文件 / 内置 TXT / 内置 MIDI」入口全部保留。

### 三、AI 音乐搭子（乐趣页 →「AI 音乐搭子」）
- **可塑人格**：5 个预设（元气搭子 / 温柔陪练 / 严格教练 / 乐理教授 / 摇滚搭子）+ 自定义头像 emoji、名字、
  性格、教学风格、口头禅、语音音调/语速，保存在本机。
- **文字 + 语音对话**：平台 `SpeechRecognizer` 听写（zh-CN）+ `TextToSpeech` 朗读，可随时关闭语音；
  对话历史本地保存（最近 20 条），支持清空。
- **会做事**：回复里可带行为标签（练习 / 灯阵 / 节拍器 / 曲库等），点一下直接跳到对应页面；
  结合当前设备状态、当前曲目、连续打卡与最近评分给建议；评分卡新增「让 AI 搭子点评这轮」。

### 四、其他 AI 增强
- **AI 灯效导演**（灯阵 → 灯效场景）：一句话描述氛围（如「夏夜湖边安静地呼吸」），DeepSeek 返回
  模式/方向/速度/亮度参数，仍然走原有 `LED:` 指令应用，可继续手动微调。
- **练习点评**：评分卡新增「AI 搭子点评这轮」，把本轮正确/错音/漏弹与曲目上下文交给搭子给出鼓励 + 可执行建议。
- **上下文感知**：App 只发送必要的文本上下文（是否连接、当前曲目、打卡天数、最近评分），不发送 Key。

### 五、练习页排版重排（v3.12.0 追加）
- 练习页固定为 5 段：**本次练习摘要**（曲名/时长/音符数/同步状态 + 开始练习/换一首）→ **跟弹练习**

### 六、权限、隐私与安全说明
- 新增权限：`RECORD_AUDIO`（仅语音对话；不使用语音不会请求）+ 语音识别/TTS 的 `<queries>` 声明。

  因此**生产环境建议**：使用限额/可轮换的专用 Key，或改为自建后端代理下发临时令牌；不要用主账号 Key。

- AI 生成内容均需人工校对；搜索/抓取按 DeepSeek 官方计费规则按次收费。
- 联网/模型能力说明：图像理解模型为 `deepseek-flash`；`deepseek-v4-pro` 无视觉，不能用于识图。

## v3.8.4 / v3.8.5：全屏跟弹改为横向时间轴 + 判定宽容度修正

**问题**：横屏全屏跟弹一次只能看到寥寥几个音，「感觉很赶」。

**根因**（`SongGuideView` 原实现）：四条弦泳道**横着铺满整个宽度**（宽度被四等分），
而时间沿**高度**自下而上流动。于是横向只剩 **4 个时间位置**，4000ms 全挤在约 370dp 的高度里 ——
长度方向明明有 800dp 却没用上。

**改法**：把时间轴转到长度方向：

| | 旧 | 新 |
|---|---|---|
| 纵向 | 时间（自下而上，仅 ~370dp） | **四条弦**（1/2/3/4 从上到下） |
| 横向 | 四条弦泳道（仅 4 个时间位置） | **时间（左 → 右，~795dp）** |
| 弦名 | `A 弦 / E 弦 / C 弦 / G 弦`（字母） | **`1 / 2 / 3 / 4`**（数字为主，小字「弦」以免与品位混淆） |
| 弦序 | 自下而上 G→A | **自上而下 1(A) → 4(G)** |

效果（2400×1080 @2.75 横屏实测推算）：时间轴从 ~258dp 增加到 **795dp（约 3 倍）**，
120 BPM 下 4 秒内可见约 **16 个八分音符**（旧布局约 5~6 个）。
音符直径按弦高与时间轴长度自动取值（上限 22dp、下限 12dp），频密段落不会糊成一团。
「当前应弹什么」从原来挤在底部的竖排文字改为顶部居中一行（如 `1弦 3品   3弦 空弦`）。

## v3.8.5：评分不再「只有扫到正中间才算对」

**问题**：用户反馈「只有基线扫到音符块的中间再按正确的弦才判定正确」。

**根因**（`PracticeScorer` 原实现）：判定窗口是固定 ±300ms，但每个音符的窗口会被**相邻音符的中分点裁掉**：

| 速度 | 八分音符间隔 | 理论窗口 | 裁剪后实际窗口 |
| --- | --- | --- | --- |
| 60 BPM | 500ms | ±300ms | ±250ms |
| 120 BPM | 250ms | ±300ms | **±125ms** |
| 160 BPM | 188ms | ±300ms | **±94ms** |

而视觉上的音符块是**固定 44dp 宽**（在时间轴上约相当于 221ms），于是「看着还在块里」却已经超时判错。
更关键的是：拨弦反馈是在手机**收到 BLE 通知**的那一刻计时的（`PlayedNoteTracker.accept(notes, now)`），
到达时已经晚于实际拨弦 20～150ms —— 所以**弹在拍点上也会被判成偏晚**。

**改法**：
1. **宽容度按音符时长自动取**（`TOKEN_MIN_MS=120 / TOKEN_MAX_MS=300`，`RULE_VERSION=2`）：
   取 `120ms + 到下一个音符的间隔`，上限 300ms。以相邻中分点为硬边界（因此不会把上一个音算成下一个音）。
2. **新增「设置 → 评分宽容」**（准时 / 标准 / 宽松 = 0 / 80 / 160ms 前移）抵消设备反馈延迟，
   默认「标准」。导航视图读同一个值，所以**画面位置与判定窗口始终一致**。
3. **音符块宽度改为等于真实判定窗口**：画面上「基线落在块内」＝「这一下会被判对」，
   看到的和判到的终于一致（兜底不小于音符直径，极快段落也看得见）。

**可复现的验证**（纯 JVM，无需设备）：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\verify_scoring\run.ps1
```

输出（`RULE_VERSION=2`，默认「标准」80ms）：

```
120 BPM eighth (250ms) -> EARLY -40 ms  LATE +125 ms
160 BPM eighth (188ms) -> EARLY -10 ms  LATE +90  ms
[PASS] on-beat hit scores CORRECT
[PASS] 120BPM: -125ms (old edge) now CORRECT
[PASS] 160BPM: -94ms (old edge) now CORRECT
[PASS] 120BPM: hit past midpoint is NOT credited to previous note
[PASS] wrong pitch is not CORRECT
[PASS] unplayed note becomes MISSED
RESULT: all checks passed
```

> 注意：`RULE_VERSION` 从 1 升到 2，成绩记录的键（`PracticeScoreRecords.key`）会把规则版本算进哈希，
> 所以**旧规则下的历史最高分不会与新规则混用**（旧记录文件仍在，只是不再显示）。
> 这是有意为之：判定标准变了，成绩不该直接沿用。

# 尤克里里手机端控制台

当前交付版本 **3.2.6**（`versionCode 16`）。本轮为**界面与组件体系的现代化重构 + 新增「应用设置」**；
演奏、灯阵、曲谱与 BLE **协议格式**均未改动（3.2.2/3.2.3 只调整了连接管理策略，见下方「连接稳定性」）。
双向设置同步需要配套新版 ESP32 固件及屏幕事件脚本，
见 APP与屏幕同步更新说明.md（历史路径：`APP与屏幕同步更新说明.md`）。本轮已编译并出包，**尚未安装到真机验证**。

> **3.2.2 – 3.2.6 连接稳定性改动**（协议格式未变，只改连接策略）
> - 切换主题/字号**不再断开蓝牙**，也不会中断设备上正在播放的曲子。
> - 非预期掉线会**自动重连**（上限 3 次、2/4/6 秒递增、仅前台且开启自动重连时）；
>   只有连接**稳定在线 30 秒**才重置重试次数，避免「连上就掉」的设备无限重连。
>   在后台掉线时也会记住这次「稳定」信度，回前台仍能补足重试次数。
> - 写入超时改为**进度看门狗**：每成功写完一包就重新计时，阈值 8s→12s，
>   并且只有「队列还有待发数据」时才计时；同时修掉了「连接后第一次写入没有看门狗、
>   回调一旦丢失就永久卡在发送中」的窗口。
> - 扫描改为可重启（重复点击不会被旧超时掐死），断开时也会真正停止扫描，
>   不再是「点了断开、后台还在扫描并且可能自己连上」。
> - **仍未解决（已知问题）**：一次上传有 N 包时，只要有一包超过 12 秒没写完就会断开重连，
>   失败率随包数放大（约 `1-(1-p)^N`）。曾尝试「超时先重发同一包、重发失败再断开」，
>   但 `onCharacteristicWrite` 不携带标识、迟到回调会把「正在重发的那一包」误 poll 掉
>   （导致队列错位、上传提前判定完成甚至漏发分片），在无真机验证手段的前提下已撤销。
>   需要真机 + 抓包定位根因后再处理。

这个 Android 工程对应 ESP32 的 BLE 服务 `6b1e0001-8f3a-4c2b-9d5e-1a2b3c4d5e6f`，实现：

- 屏幕侧同等控制：音量、两套音色、LED 模式/行列方向；
- 订阅 FPGA→ESP32→手机的实时波形（`0007`）和 ESP32 128 点 FFT 频谱（`0006`）；
- 通过 URL 调用系统下载器，或选择本地 `.uks` 文件；下载完成后自动上传到 ESP32；
- 曲谱播放/停止，LED 单点指引由 ESP32 按时间发送到 FPGA。

## 曲谱文件格式

文件是二进制 `UKS1`：8 字节头 `55 4B 53 31 01 00 count_lo count_hi`，之后每个事件 6 字节：
`delta_ms_lo, delta_ms_hi, column_mask, row(0..17), brightness, flags`。列位图 bit0..bit3 从左到右。ESP32 接收上传分片后校验 CRC32，完整文件才替换 `/song.bin`。

手机端也接受 UTF-8 文本曲谱，每行写成 `delta_ms,column_mask,row,brightness,flags`，前三列必填，后两列可省略（默认 180/0）；允许 `#` 注释和 `0x` 十六进制列位图。例如 `0,0x1,4,220,0` 表示立即点亮左边第 4 行。

## 构建

本工程可以用 Android Studio 打开运行，也提供了**不依赖 Gradle 的命令行脚本**。

```powershell
powershell -ExecutionPolicy Bypass -File .\build_apk.ps1
```

### 三个必须知道的构建约束（脚本已自动处理）

1. **`aapt2` 无法处理含非 ASCII 字符的路径。** 若工程目录名含中文（例如 `D:\APP优化\...`），
   直接编译会报 `failed to open directory`。脚本会自动把工程镜像到纯 ASCII 暂存目录
   （默认 `D:\AndroidDev\uke_build_stage`）后再构建，并把 APK 复制回工程。
   **源码始终以本工程目录为准**，暂存目录是每次构建自动重建的副本。
2. **Windows PowerShell 5.1 会把外部工具的 stderr 警告当成终止性错误**，
   而 `javac` 的 deprecation 提示正是走 stderr。脚本因此显式运行外部命令并检查退出码，
   避免把「警告」误判为「失败」，也避免把真实失败当成成功。
3. **不要用 `javac -source 8 -target 8`。** 在 JDK 17 下该组合会产生「未设置引导类路径」警告，
   并导致**产出 0 个 class 文件**（静默失败）。字节码版本由 `d8 --min-api 26` 负责。

迭代期想快速校验语法与资源，用：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\compile_check.ps1
```

它会先做 `aapt2 compile` + `aapt2 link`（校验资源与清单），再 `javac` 编译全部源码，
输出隔离在 `D:\AndroidDev\uke_check_<pid>`，因此可以多人/多任务并发运行，不会互相干扰。

构建产物：

- `D:\AndroidDev\apk_build\ukulele-monitor-debug.apk`（或 `-OutDir` 指定目录）
- 工程内副本：`build\outputs\apk\debug\UkuleleStudio-v<版本>-debug.apk`
- 版本归档副本：`dist\UkuleleStudio-v<版本>-debug.apk` 与工程根目录同名文件

这是 debug 签名包，可直接安装到测试手机；发布包再用团队自己的签名密钥重签。
