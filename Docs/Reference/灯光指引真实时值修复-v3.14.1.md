# 灯光指引真实时值修复 · v3.14.1

2026-10-19。只更新新板配套 App 和 ESP32；FPGA 保持 2893、串口屏与旧板保持原样。

## 安装与使用

1. 覆盖安装 `App/Install/UkuleleStudio-v3.14.1-debug.apk`，保持原应用签名，不必卸载原版。
2. Arduino 打开 `ESP32/Source/esp32_ukulele/esp32_ukulele.ino`，按原 ESP32 开发板配置编译烧录；不要打开根目录历史版 ESP32 工程，不清除全部 Flash/NVS。本包已包含实际编译结果。
3. 连接乐器，重新选择并上传曲谱，再开始灯光指引。设备里先前保存的旧曲谱不会隔空改变，必须重新上传。
4. 已保存的 MIDI 首次重选时，会从手机曲库保留的原 MIDI 重新生成精确时值并保存，无需删除、重新导入。原件和曲库条目继续保留。
5. FPGA 2893 不需要重烧。只安装 App 而不更新 ESP32，旧固件不能接收 v2 曲谱。

## 问题原因

旧 MIDI 导入路径主要保留音符开始时刻，丢掉 Note Off，灯光便会持续到下一个事件，即使中间实际上是空拍。滚动跟弹的部分音块又沿用评分容差窗口作为宽度，两者都不能代表真正音长。

现在 MIDI 导入使用完整解码器，按 Note On / Note Off、速度变化、延音踏板和文件结束位置计算音符区间。App 的滚动音块、曲谱合成试听、ESP32 灯光目标使用同一份区间。原 MIDI 试听仍播放原文件真实内容；为区分重复拨弦而设置的短灭灯间隔是演奏提示，不修改原 MIDI 文件。

## 实际行为

- 休止：所有弦无有效音符的区间，下发四弦关闭目标，而不是延续上一音。
- 多音：每根弦独立结束；一根弦结束时只熄灭该弦，其他持续音继续指引。
- 重复音：同弦同品相邻重复音在下一次开始前留短灭灯间隔，通常为60毫秒曲谱时间，最多不超过相邻起音间隔的一半；原有起音时刻不后移。自然空拍更长时保持自然空拍。倍速会同步缩放这个间隔。
- 长音：跨越65,535毫秒分段仍保持原音，不会错误熄灭或重复计分。
- 曲尾：保留 MIDI 文件中的尾部休止，不再固定把最后一音额外亮500毫秒。
- 暂停：先处理已到期的结束事件，再冻结时钟；在空拍边界暂停不会把上一音一直留亮。
- 评分：延续中的音不是新攻击，只对实际新起音计分；评分容差与视觉音长分开。
- 曲谱选择：旧 MIDI 转换在后台执行，较大的文件不阻塞主界面；识谱后“开始练习”会等待对应曲谱真正载入，快速切歌不会被较慢的旧加载覆盖。
- 指引结束或手动停止后，恢复开始前的普通 LED 模式；此前若是常亮，结束后灯阵会恢复常亮。这与曲内空拍的关闭行为不同。

没有真实音长信息的时间文本不能唯一恢复原谱休止；这类旧数据沿用相邻事件区间。照片/PDF需要识谱结果中正确的音长、休止信息；本轮不凭空猜测缺失节奏。

## 协议

文件魔数仍是 `UKS1`，头部版本由1扩展为2；总头长8字节、每记录6字节不变。

| 字节 | 含义 |
|---|---|
| 头0..3 | ASCII UKS1 |
| 头4 | 版本2；ESP32继续兼容版本1 |
| 头5 | 0 |
| 头6..7 | 记录数量，小端16位 |
| 记录0..1 | 距上一组的毫秒数，小端16位；0表示同一时刻的组内下一行 |
| 记录2 | 弦掩码，G/C/E/A分别为位0/1/2/3；0表示全灭 |
| 记录3 | 品位0..18 |
| 记录4 | 亮度，发光记录为1..255；休止为0 |
| 记录5 | 0=新起音；0x80=延续此前同弦同品的音 |

版本2的同一时刻各行共同描述四根弦的完整状态，未出现在组内的弦关闭；所有行收齐后再提交目标，不能用单条音符覆盖和弦。延续行只用于描述持续音，不重新试听/计分。结束组必须全灭。超过65,535毫秒的间隔分段发送相同状态，持续音用0x80标记。

App和ESP32校验：版本、保留字段、总长度、记录数量、掩码、品位、亮度、标志、最长两小时、同组弦重复/休止冲突、非法延续及最终全灭。原有上传CRC/回复流程保留。超出设备容量明确拒绝，建议分曲，不静默删音。

现有 FPGA 命令0x20、14字节BLE灯光通知0x90/0x16，以及20字节播放状态0x91均保持；没有扩展BLE通知长度，也没有挪用控制状态保留字节。FPGA无需增加寄存器或音频资源。
