## 0. 本文档管什么、不管什么（重要，先读这段）

系统里有**两条完全独立的通信链路**，别混淆：

```text
[AD7147×8 / ADS7950 / LP5860]  ──SPI──►  [FPGA]  ──UART帧──►  [ESP32]  ──BLE──►  [手机 App]
        传感器/执行器                      实时主控                旁路学习/联网
      ▲ 本文档不涉及 ▲                  ▲ 本文档全部内容 ▲         ▲ 本文档不涉及 ▲
```

| 链路 | 协议 | 速率 | 传什么 | 定义在哪 |
| --- | --- | --- | --- | --- |
| FPGA ↔ 传感器/灯阵 | **SPI**（AD7147 32 位事务 / ADS7950 16 位帧 / LP5860 2 字节地址+数据） | 2 MHz / 2 MHz / ≤12 MHz | 原始 CDC 电容值、ADC 采样值、LED 寄存器 | `docs/芯片与信号采集链路方案.md`、`docs/系统信号流图与通信方案.md` §7 |
| **FPGA ↔ ESP32** | **UART 帧**（本文档） | 1 Mbps | **已处理好的结果**：触摸位图/品位/拨弦事件/阈值表 | **本文档** |

**为什么本文档里没有 SPI**：

1. SPI 是**芯片级时序**（读寄存器、写寄存器），由 FPGA 内部的状态机消化，**ESP32 完全不接触传感器总线**（V2 架构的核心决策，见 `docs/电容触摸阈值方案.md` §1.1）；
2. ESP32 需要的是"**结论**"（哪根弦、第几品、力度多少），不是 32 位的 SPI 事务；
3. 如果 ESP32 确实需要原始数据（例如标定），FPGA 会把 **SPI 采样结果打包进 UART 帧**送出来 —— 这就是 **TYPE `0x22` 原始 CDC 流**（§4.1），它正是 SPI 数据进入 UART 帧的唯一入口。

> 一句话：**SPI 在 FPGA 里面，UART 帧在 FPGA 外面**。本文档只定义"外面"。

| 项 | 值 | 说明 |

## 2. 帧结构（固定 5 字节头 + 可变载荷 + 1 字节 CRC）

```text
┌──────┬──────┬─────┬──────┬─────┬───────────────┬──────┐
│ SYNC0│ SYNC1│ LEN │ TYPE │ SEQ │   PAYLOAD     │ CRC8 │
│ 0xAA │ 0x55 │ 1B  │ 1B   │ 1B  │  0..200 B     │ 1B   │
└──────┴──────┴─────┴──────┴─────┴───────────────┴──────┘
  偏移0   1     2     3      4     5 .. 4+LEN      5+LEN
```

| 字段 | 长度 | 取值 | 说明 |
| --- | --- | --- | --- |
| `SYNC0/SYNC1` | 2B | `0xAA 0x55` | 帧同步字，固定 |
| `LEN` | 1B | 0..200 | **PAYLOAD 字节数**（不含头/CRC）；>200 视为错误帧 |
| `TYPE` | 1B | 见 §4 | 帧类型 |
| `SEQ` | 1B | 0..255 循环 | 帧序号；用于 ACK 配对与丢帧检测 |
| `PAYLOAD` | LEN | — | 见 §4；多字节字段**小端**（低字节在前） |
| `CRC8` | 1B | — | 覆盖 **`LEN`、`TYPE`、`SEQ`、`PAYLOAD`**（不含 SYNC） |

**CRC 参数（CRC-8/ATM）**

| 项 | 值 |
| --- | --- |
| 多项式 | `0x07`（x⁸+x²+x+1） |
| 初值 | `0x00` |
| 输入/输出反射 | 否 |
| 结果异或 | `0x00` |
| **标准校验向量** | `CRC8("123456789") = 0xF4` ← 实现后用这个自测 |

## 3. 示例帧（真实字节，可直接用于自测）

| 用途 | 十六进制 |
| --- | --- |
| **心跳帧**（TYPE 0x23，SEQ=01，ver=0101，scan_us=22，frames=1000，mismatch=0，flags=80，err=00，last_word=0x094E，addr_err=0） | `AA 55 0E 23 01 01 01 16 00 E8 03 00 00 80 00 4E 09 00 00 76` |
| **版本查询**（TYPE 0x15，SEQ=02） | `AA 55 00 15 02 18` |
| **ACK**（TYPE 0x05，SEQ=01，应答 SEQ=02，状态=00） | `AA 55 02 05 01 02 00 CB` |
| **阈值表块**（TYPE 0x12，8 通道，LEN=50） | `AA 55 32 12 01 …50B 载荷… C1` |

> 心跳帧逐字节解析：`AA 55` 同步 → `0E`=载荷 14 字节 → `23`=心跳 → `01`=序号 →
> `01 01`=ver → `16 00`=scan_us(22) → `E8 03`=frames(1000) → `00 00`=mismatch(0) →
> `80`=flags(链路健康) → `00`=err → `4E 09`=last_word(0x094E，地址 0/码值 2382) →
> `00 00`=addr_err_cnt(0) → `76`=CRC。

## 4. 帧类型总表

### 4.1 上行（FPGA → ESP32）

| TYPE | 名称 | 周期 | PAYLOAD 布局 |
| --- | --- | --- | --- |
| `0x20` | 状态帧 | 10 ms | `TS(4)` + `touch_bitmap(13)` + `fret(4×1)` + `strum_env(4×2)` + `chips_ok(1)` = **30 B** |
| `0x21` | 拨弦事件 | 事件驱动 | `TS(4)` + `弦(1)` + `峰值(2)` + `品位(1)` + `力度(1)` = **9 B** |
| `0x22` | 原始 **CDC 值**流 | 50 ms（仅标定模式，20 Hz） | `TS(4)` + `start_ch(1)` + `n(1)` + `CDC(2)×n` |
| `0x23` | 心跳/诊断 | 1 s | `ver(2)` + `scan_us(2)` + `frames(2)` + `mismatch(2)` + `flags(1)` + `err(1)` + `last_word(2)` + `addr_err_cnt(2)` = **14 B** |
| `0x24` | **光电原始值**（ADS7950） | 50 ms | `TS(4)` + `n(1)` + `raw16(2)×4` + `dip(2)×4` + `peak(2)×4` + `base(2)×4` + `mismatch(2)` + `frames(2)` = **41 B**（`n=18`）；`raw16` 高 4 位 = 通道地址（自检）、低 12 位 = 码值（VREF=2.5 V → 1 LSB = 610.35 µV） |
| `0x05` | ACK | 收到下行帧后 | `ack_seq(1)` + `状态(1)`（0=OK，非 0=错误码） |

> `TS` = FPGA 50 MHz 计数值（低 32 位）→ 1 LSB = 20 ns；除以 50 得 µs。用于延迟测量与事件排序。
> `touch_bitmap` = 97 位（13 字节，最高字节仅低 1 位有效），bit n 对应 `ch_id n`。
> **0x23 心跳不含 `TS` 与 `chips_ok`**（这两个字段在 0x20 状态帧里）。心跳各字段含义：
> `ver` 固件版本；`scan_us` = ADS7950 一轮扫描耗时（实测 22 µs = 277 clk/字 × 4）；
> `frames` = SPI 收到字数；`mismatch` = 回传地址与"2 帧前请求的通道"不符的次数（正常应恒为 0）；
> `flags` bit7 = 本秒有新帧且无不匹配（链路健康）；`err` = 下行帧 CRC/同步错误计数；
> `last_word` = 最近一帧 SDO 原始回传字 —— **判断 SPI 链路是否活着的唯一可靠指标**：
> `0xFFFF` = ADC 没驱动 SDO、`0x0000` = 被拉低、`0x0xxx~0x3xxx` = 正常（高 4 位即通道号）；
> `addr_err_cnt` = 返回地址不在 0~3 的次数。

### 4.2 下行（ESP32 → FPGA）

| TYPE | 名称 | PAYLOAD 布局 |
| --- | --- | --- |
| `0x10` | 进入标定 | 空 |
| `0x11` | 退出标定 | 空（FPGA 校验整表 CRC 后原子切换） |
| `0x12` | 阈值表块 | `start_ch(1)` + `n(1)` + `{B(2), θ_on(2), θ_off(2)}×n`（n ≤ 8） |
| `0x13` | 参数设置 | `k(1)` + `η(1)` + `EMA步进(1)` + `防抖(1)` + `共模开关(1)` + `ADS档(1)` |
| `0x14` | 恢复出厂 | 空 |
| `0x15` | 版本查询 | 空 |
| `0x16` | 学习器增量 | `start_ch(1)` + `n(1)` + `{Δθ(2,有符号), ΔB(2,有符号)}×n` |
| `0x17` | LED 指引 | `模式(1)` + `数据…`（单格/整行/曲谱序列） |

## 5. 会话流程

### 5.1 正常运行（无标定）

```text
FPGA ──0x20 状态帧(10ms)──► ESP32        （App 显示/学习器统计）
FPGA ──0x21 拨弦事件──────► ESP32        （力度/录音/回放）
FPGA ──0x23 心跳(1s)──────► ESP32        （掉线检测）
ESP32 ──0x17 LED 指引─────► FPGA ──0x05 ACK──►
```

### 5.2 标定会话（完整握手）

```text
ESP32 ──0x10 进入标定─────► FPGA ──0x05 ACK──►
ESP32 ◄──0x22 原始 CDC 流×200 轮── FPGA    （静置采样约 11 秒，每通道 200 样本）
ESP32 计算 B₀=median、σ₀=MAD
ESP32 ──0x17 点亮第 n 格──► FPGA ──0x05 ACK──►
ESP32 ◄──0x22 该格响应流────── FPGA       （10 次/格 → 响应幅度 A）
ESP32 生成 θ = max(k·σ₀, A×0.25, θ_floor)
ESP32 ──0x12 表块 ×13─────► FPGA ──0x05 ACK──►  （写入影子表）
ESP32 ──0x13 参数─────────► FPGA ──0x05 ACK──►
ESP32 ──0x11 退出标定─────► FPGA            （整表 CRC 通过 → 原子切换）
                        ◄──0x05 ACK────────
```

## 6. 错误处理与重同步

| 场景 | 处理 |
| --- | --- |
| CRC 错 | 丢弃该帧，`err_cnt++`；连续 3 次错 → 解析状态机复位，重新找同步字 |
| LEN > 200 | 丢弃，从当前字节重新搜索 `AA 55` |
| 下行帧 300 ms 无 ACK | 发送方重传，最多 3 次；仍失败 → 上报 App 提示检查连线 |
| 帧头误同步 | 采用"状态机 + CRC 双重确认"：只有 CRC 通过才认为同步成功 |
| ESP32 掉线/未连接 | FPGA 继续用当前表演奏；上电无表时用默认保守参数 + 自动学基线 |
| 表只写了一半 | 双缓冲：影子表全部写完 + `0x11` + 整表 CRC 校验通过才切换 |

**接收状态机（两侧同构）**：

```text
WAIT_AA → WAIT_55 → READ_LEN → READ_TYPE → READ_SEQ → READ_PAYLOAD(LEN)
   → READ_CRC → 校验 ─┬─ 通过 → 交给上层，回 WAIT_AA
                      └─ 失败 → 丢弃 + err_cnt++，回 WAIT_AA
任何状态收到非法值/超时（>2 ms 无字节）→ 回 WAIT_AA
```

## 8. 实现约定

### 8.1 FPGA 侧

| 模块 | 职责 |
| --- | --- |
| `uart_tx.v` / `uart_rx.v` | 1 Mbps 收发；RX 采用 16× 过采样取中点采样 |
| `crc8.v` | 组合/流水线实现，参数见 §2 |
| `frame_tx.v` | 从 FIFO 取载荷 → 组帧 → 送 uart_tx；发送中不接受新帧 |
| `frame_rx.v` | §6 状态机 → 校验 → 输出 `{type, seq, payload}` + 有效脉冲 |
| `frame_dispatch.v` | 按 TYPE 分发：命令 / 表写 / 参数 |
| `table_ram.v` | 双缓冲阈值表（2 × 97 × 6B = 1164B，BSRAM） |
| 发送 FIFO | 256 B 环形；满时丢弃状态帧（保事件帧） |

### 8.2 ESP32 侧

| 模块 | 职责 |
| --- | --- |
| UART 驱动 | UART2 @1 Mbps，DMA/中断 + 环形缓冲（≥2 KB） |
| 解析器 | §6 状态机；帧回调 `on_frame(type, seq, payload, len)` |
| 组帧器 | 下行帧构造 + ACK 等待/重传 |
| 上层 | 标定算法、学习器、BLE 服务、NVS 档案 |

## 9. 测试计划（从零到联调，5 步）

| 步骤 | 内容 | 验收标准 |
| --- | --- | --- |
| **1** | FPGA 每 1 s 发**心跳帧**，PC 串口助手（HEX）接收 | 收到的十六进制与 §3 示例逐字节一致 |
| **2** | PC 发**版本查询**（`AA 55 00 15 02 18`），FPGA 回 **ACK** | 收到正确 ACK；SEQ 配对 |
| **3** | DL16 逻辑分析仪抓 TX | 位宽 = **1 µs**（1 Mbps）；帧间隔符合预期；无毛刺 |
| **4** | 连续压测 + 错误注入 | 10000 帧 0 错；人为改 1 位 → 接收端丢弃并 `err_cnt++` |
| **5** | 对端换成 **ESP32** | 双向握手、表下发、ACK、断线恢复全部通过 |

> 步骤 1~4 **不需要 ESP32、不需要 AD7147/ADS7950**，只要开发板 + PC 串口助手 + DL16 就能全部完成。
