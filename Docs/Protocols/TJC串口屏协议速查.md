## 0. 一句话结论

屏幕说 **“淘晶驰字符串协议”**：**ESP32 发一条 ASCII 明文指令 + `FF FF FF` 三字节结束符**；屏幕回数据也是 **`功能码 + 载荷 + FF FF FF`**。**下行没有帧头**，**上行触摸事件没有 0x55 帧头**。
（主手册 p.225 / p.229 / p.900–906 / wiki/debug/connect_mcu）

## 1. 下行帧格式（ESP32 → 屏幕）

### 1.1 默认模式（被动解析 / 淘晶驰字符串协议）

```
[ ASCII 指令明文（无帧头） ] [ 0xFF 0xFF 0xFF ]
```

- **无帧头、无长度字段、无校验**。属“帧内容 + 帧尾”结构。(主手册 p.229：“淘晶驰通讯协议是帧内容+帧尾（3 个 0xff）”)
- **结束符固定 3 个 0xFF**，是**十六进制字节**，不是字符 `'F'`。(主手册 p.225、p.1310)
- 无长度字段；屏幕按“收到 3 个连续 0xFF”判断一条指令结束。(主手册 p.225、p.1310)
- **不需要转义 0xFF**；指令载荷是 ASCII 文本，天然不会出现 0xFF。**【推断】**（文档中未见任何对下行数据转义 0xFF 的要求）

**关键区别（容易踩坑）**：`0x55` **不是**淘晶驰协议的帧头。

> 主手册 p.229 明确写：“淘晶驰**没有定义固定的**串口屏发送给单片机的数据格式，您需要自己定义格式”，并列出了自定义协议示例 `55 01 00 ff ff ff`（帧头 55 + 编号 + 状态 + 帧尾 ffffff）；p.338 的 ESP32 例程里 `0x55` 是**用户自己定义的帧头**。
> 所以：**`0x55` 出现在官方例子里，但它属于“用户自定义协议”的示例，不是屏幕协议的一部分。**

### 1.2 完整示例

| 目的 | ASCII（不含结束符） | ESP32 实际发送的字节（hex） |
|---|---|---|
| 切到 main 页 | `page main` | `70 61 67 65 20 6D 61 69 6E FF FF FF` |
| 切到第 2 页 | `page 2` | `70 61 67 65 20 32 FF FF FF` |
| 文本 t0 写 “Hello” | `main.t0.txt="Hello"` | `6D 61 69 6E 2E 74 30 2E 74 78 74 3D 22 48 65 6C 6C 6F 22 FF FF FF` |
| 数字 n0 写 100 | `setting.n0.val=100` | `73 65 74 74 69 6E 67 2E 6E 30 2E 76 61 6C 3D 31 30 30 FF FF FF` |
| 全局变量 sys0=123 | `sys0=123` | `73 79 73 30 3D 31 32 33 FF FF FF` |
| 亮度 80% | `dim=80` | `64 69 6D 3D 38 30 FF FF FF` |
| 复位 | `rest` | `72 65 73 74 FF FF FF` |
| 开机清缓冲“空指令” | `\x00` | `00 FF FF FF` |

（主手册 p.225 / p.578 / p.855 / p.835 / p.634 / p.1317）

### 1.3 主动解析模式（自由协议，`recmod=1`）

- 屏幕不再解析淘晶驰字符串指令；用户自己在**定时器控件**里读串口缓冲区数组 `u[index]`，自己找帧头帧尾、自己校验。(主手册 p.947–p.948)
- 缓冲区大小：`usize`；T1 为 **1024 字节**，`u[0]~u[1023]`。(主手册 p.1430、规格书 p.13)
- 相关指令：`ucopy`（拷贝）、`udelete`（删前 N 字节）、`code_c`（清空）。(主手册 p.710 / p.948 / p.952 / p.954)
- **本项目不建议用**，用默认被动模式即可。(主手册 p.947 “大多数项目用不上”)

## 2. 常用指令写法（可直接照抄）

### 2.1 书写语法铁律（违反必然报错）

| 规则 | 说明 | 来源 |
|---|---|---|
| **等号两边绝对不能有空格** | `t0.txt = "123"` ❌ → 报错 | 主手册 p.832 |
| **语句末尾不能有分号** | `t0.txt="123";` ❌ | 主手册 p.834 |
| **一行只能一条赋值** | `t0.txt="123" t1.txt="456"` ❌ | 主手册 p.834 |
| **字符串属性必须加双引号** | `t0.txt=123` ❌，`t0.txt="123"` ✅ | 主手册 p.832、p.1302 |
| **数值属性不能加双引号** | `j0.val="50"` ❌ → 返回 `1B FF FF FF` | 主手册 p.891 |
| **字符串↔数值不能直接赋值** | `t0.txt=n0.val` ❌，要用 `covx` | 主手册 p.833、p.852 |
| **变量名最长 29 字符** | 超出返回 `23 FF FF FF` | 主手册 p.899 |
| **所有变量名用小写** | “所有变量名称使用小写字符” | 主手册 p.745 |

### 2.2 切页

```
page main          // 用页面名（官方推荐）
page 2             // 用页面 ID
dp=2               // 等价的写法，给系统变量 dp 赋值
```
- 主手册 p.576 / p.578：“推荐使用 page + 页面名称”。ID 就是上位机页面窗口里显示的“页面id”(p.75)。
- ⚠️ **`page` 后面的代码永远不执行**（官方连喊 8 遍）。(主手册 p.576–577)
- 返回上一页：读取/使用 `dp`（主手册 p.748 章节）。

### 2.3 文本控件赋值（`txt`，字符串型）

```
main.t0.txt="Hello"
t0.txt="abc"
t0.txt+="追加内容"            // += 追加（分段发送长文本用，见 §8.4）
t0.txt=t1.txt                 // 控件间抄
main.t0.txt=set.t3.txt+"abc"  // 拼接
t1.txt="123"                  // 引号里的 123 是字符串，不是数字
t2.txt=t0.txt+t1.txt          // 字符串 + 字符串 = 拼接 → "123456"
```
（主手册 p.831–834、p.852、p.1303）
- 显示不全 → 增大控件的 `txt_maxl` 属性（只能用上位机改，不能用指令改）。(主手册 p.855、p.1425、p.480)

### 2.4 数值控件赋值（`val`，signed int32）

```
setting.n0.val=100
n0.val=12345
n0.val=n0.val+1               // 数值运算
n2.val=n0.val+666
n0.val=87*100/88              // =98，整数除法（屏不支持浮点）
sys0=n0.val
n0.val=-500                   // 范围 -2147483648 ~ 2147483647
```
（主手册 p.835、p.1303、p.1338、p.172、p.480）

### 2.5 进度条（`j0`）

进度条就是数值控件，改 `val` 即可：
```
j0.val=50                     // 0~100
j0.val+=10
```
- **数值范围是 0~100**，是百分比语义；赋负数返回 `1C FF FF FF`。(主手册 p.892 举例“给进度条赋值为负数”；**范围 0~100 属【推断】**，上位机属性栏默认 min/max 为 0/100，建议实测)
- 【需实测确认】进度条 `val` 是否严格 0–100 截断，还是按 `minval/maxval` 自定义。

### 2.6 曲线波形控件送数据（`s0`）

**方式 A：`add` 逐点（推荐，简单）**
```
add s0.id,0,30        // 往 s0 的 0 通道加一个点，值为 30
add s0.id,1,n0.val    // 1 通道加 n0.val（ch 属性需 ≥2）
add s0.id,0,rand      // 加随机数
```
- `objid` **必须是 ID 号**，不支持控件名；推荐写 `s0.id` 形式（避免置顶/置底改 ID 后出错）。(主手册 p.623)
- `ch` 通道号 **从 0 开始，范围 0–3**。(主手册 p.623)
- `val` **8 位数据，0–255**；超过 255 自动取低 8 位（对 256 取模）；超过控件像素高度部分不显示。(主手册 p.623、p.626)
- **通道数为 1 时只有通道 0 可用，不是通道 1**。(主手册 p.626)
- **每个页面最多 4 个曲线控件，每个控件最多 4 个通道**。(主手册 p.626)
- **add 不支持跨页面**。(主手册 p.623、p.627)

ESP32 循环送 100 点（官方 C 例程，主手册 p.627）：
```c
for (int i = 0; i < 100; i++)
    printf("add s0.id,0,%d\xff\xff\xff", rand() % 256);
```

**方式 B：`addt` 二进制透传（高速，适合波形）**
```
addt s0.id,0,100      // 通道 0 准备接收 100 个点
```
握手与数据流（主手册 p.628）：
1. 发 `"addt s0.id,0,100" + FF FF FF`
2. 等屏幕回 **`FE FF FF FF`**（就绪；初始化约 5ms，T/K 系列更久）
3. 发 **100 字节纯 16 进制数据**（无字符串、**无结束符**）
4. 屏幕回 **`FD FF FF FF`**（透传完成），此时曲线才刷新
- **单次透传最大 1024 字节**。(主手册 p.628)
- **清空曲线**：`cle s0.id,0`（主手册 p.632）。

### 2.7 读回控件值（`get`，带格式返回）

```
get t0.txt        // 字符串 → 回 70 + 内容ASCII + FF FF FF
get j0.val        // 数值   → 回 71 + 4字节小端 + FF FF FF
```
例：`get j0.val`，`val=50` 时返回 `71 32 00 00 00 FF FF FF`（32 是 16 进制的 50）。(主手册 p.696–697、p.905–906)
- 也可在屏幕脚本里 `prints t0.txt,0` 主动把变量打到串口（见 §3.4）。(主手册 p.579)

### 2.8 亮度

```
dim=50            // 当前亮度，立即生效，重启丢失，不耗 flash
dims=50           // 默认亮度，写入 flash，重启保持，耗 flash 寿命
dim=dim+10        // 相对调节
dim=dim-10
```
- 范围 **0–100**。(主手册 p.758、p.763)
- **`dims` 写在 program.s 里、`page` 指令之前**。(主手册 p.758)
- ⚠️ 官方警告：**不要把 `dims` 设为 0**，否则重启后黑屏会误判为坏了。(主手册 p.758、p.1335)
- 对照：`baud`/`bauds` 是同样的“临时/掉电保存”一对。(主手册 p.1335、p.1336)

### 2.9 复位 / 睡眠 / 其它系统开关

```
rest              // 屏幕直接重启（无需参数）
sleep=1           // 进入睡眠（亮度 0）；后面的代码不执行
sleep=0           // 唤醒
thsp=30           // 30 秒无触摸自动睡眠（0=关闭，最小 3 秒）
ussp=30           // 30 秒无串口数据自动睡眠（0=关闭，最小 3 秒）
lowpower=1        // 深度睡眠（仅 T1 支持）；0=普通睡眠
wup=255           // 唤醒后回到睡眠前页面（默认）；wup=0~254 = 唤醒后跳指定页
bauds=115200      // 改默认波特率（掉电保存）
baud=115200       // 改当前波特率（重启丢失）
bkcmd=0           // 0=不返回结果 1=只返回成功 2=只返回失败(上电默认) 3=都返回
recmod=0          // 关闭主动解析
volume=100        // 音量（本型号不支持喇叭，预留写法）
```
（主手册 p.634、p.785、p.787、p.783、p.777、p.775、p.769、p.772、p.789、p.855）
- ⚠️ **禁止在 `program.s` 或它跳转到的页面初始化事件里写 `rest`，会无限重启**。(主手册 p.634)
- 睡眠中**只有 `get` / `prints` / `printh` 和 `sleep=0` / `wup=X` 能执行**，控件赋值全部失效，所有定时器停止。(主手册 p.785)
- 深度睡眠（`lowpower=1`）下唤醒会**丢掉前 ~50ms 的串口数据**；普通睡眠不丢。(主手册 p.788)

## 3. 上行数据（屏幕 → ESP32）

**通用规则：所有返回数据都以 `FF FF FF` 三字节结束。**(主手册 p.900)
**`bkcmd` 只影响第 7.1 节那批“指令执行状态”返回；第 7.2 节“其他数据返回”全部不受 `bkcmd` 影响。**(主手册 p.878、p.900)

### 3.1 触摸/点击事件 `0x65` ★最重要

```
0x65 + 页面ID(1B) + 控件ID(1B) + 触摸事件(1B) + FF FF FF
```
- **前提：必须在上位机勾选控件的“发送键值”复选框**，否则不发。(主手册 p.901、p.74)
- **触摸事件**：**按下 = `0x01`，弹起 = `0x00`**。(主手册 p.901)
- 官方例子：`65 00 02 01 FF FF FF` = **页面 0 上的控件 2 被按下**。(主手册 p.901)
- **注意**：这里给的是 **控件 ID**（不是控件名，也不是 `t0/b0` 里的数字）。控件 ID 由软件自动分配、不可手改，就是“名称组”里的 `b[id]`。(主手册 p.876、p.390)

**解析代码（ESP32/Arduino）—— 完整帧 7 字节**
```c
// 帧: 0x65 <pageID> <ctrlID> <event> 0xFF 0xFF 0xFF   → 共 7 字节
if (Serial2.available() >= 7) {
    if (Serial2.peek() == 0x65) {
        uint8_t b[7];
        Serial2.readBytes(b, 7);
        if (b[4] == 0xFF && b[5] == 0xFF && b[6] == 0xFF) {
            uint8_t page = b[1];        // 页面 ID
            uint8_t ctrl = b[2];        // 控件 ID
            uint8_t evt  = b[3];        // 0x01=按下  0x00=弹起
        }
    } else {
        Serial2.read();                 // 丢弃非帧头字节
    }
}
```
【推断】官方 p.901 只给了 4 字节片段示例 `65 00 02 01`，**没有把结尾的 3 个 0xFF 一起列出**；按 p.900“设备返回数据的结束符为 0XFF 0XFF 0XFF 三个字节”推断完整帧为 7 字节。**上板请先抓原始字节确认帧长再写死。**（见 §9 第 7 条）

### 3.2 双态按钮（`bt0`）0/1 区分 ★

- **双态按钮的状态就是 `bt0.val`：`0` = 关，`1` = 开。**“led 关闭时对应的 val 属性是 0，led 开启时是 1”。(主手册 p.229)
- **屏幕不会主动把 0/1 发给 MCU**；`0x65` 只告诉你“谁被点了、按下还是弹起”。要拿状态有两种官方途径：

**途径 A（推荐）：在屏幕的弹起事件里把 val 主动发出去**（主手册 p.229 官方做法）
```
// 双态按钮 bt0 的弹起事件里
printh 55 01              // 自定义帧头 55 + 编号 01
prints bt0.val,1          // 发 1 字节的 val（0 或 1）
printh ff ff ff           // 帧尾
```
ESP32 侧解析为 `55 01 <0|1> FF FF FF`。

**途径 B：MCU 主动读**
```
get bt0.val        // → 71 <4字节小端> FF FF FF
```
(主手册 p.906)

- 官方还演示了**用名称组的连续 ID 做互斥**：双态按钮 `bt0~bt5` 的 ID 连续时可在触摸捕捉里批量处理。(主手册 p.453)
- ⚠️ `repo`/`wepo` 往双态按钮写非 0/1 值会返回 `1D FF FF FF`（赋值异常）。(主手册 p.893)

### 3.3 触摸坐标 `0x67`（需先 `sendxy=1`）

```
0x67 + X高 + X低 + Y高 + Y低 + 触摸事件 + FF FF FF
```
- 官方例：`67 00 7A 00 1E 01 FF FF FF` = 坐标 **(122, 30)，按下**。(主手册 p.903)
- 需先把系统变量 `sendxy` 置 1；**每次点击都会发**。(主手册 p.829–830)
- 坐标为大端 16 位（高字节在前）。(主手册 p.903 示例：`00 7A` = 0x007A = 122)

### 3.4 屏幕脚本主动上报（`prints` / `printh`）

屏幕侧在自己代码里发数据，格式完全自定义：
```
printh 55 01        // 固定 16 进制（必须写成偶数个 16 进制，否则报错）
prints t0.txt,0     // 发变量/常量；数值 length 最大 4，字符串 0=整串
printh ff ff ff
```
（主手册 p.587：`printh d a` ❌ / `printh 0d 0a` ✅；p.579：`prints` 参数规则）
- **`sendme` 的替代写法**（官方推荐，因为 `sendme` 格式写死可能不匹配你的协议）(主手册 p.695)：
```
printh 66           // 0x66 = 页面 ID 返回功能码
prints dp,1         // 当前页 ID，1 字节
printh ff ff ff
```

### 4.1 改波特率

**方式 1：上位机 / 屏幕脚本（program.s，掉电保存）**
```
int sys0=0,sys1=0,sys2=0
bauds=115200        // 掉电保存，推荐
dims=100
recmod=0
bkcmd=2
page 0
```
（主手册 p.1311、p.769）
- ⚠️ **`page` 之前**写波特率配置，因为 `page` 后面的代码不执行。(主手册 p.769、p.1311)
- `bauds` 会写 flash；**每次改成不同的值消耗 flash 寿命**。(主手册 p.769)
- **要通过串口给屏幕下载工程，必须用 `bauds` 而不是 `baud`**，否则升级失败后掉回 9600 就联不上了。(主手册 p.1336)

**方式 2：运行时用指令改**
```
baud=115200         // 当前波特率，重启失效，不耗 flash
bauds=115200        // 默认波特率，写 flash，且会同时改 baud
```
（主手册 p.772、p.1336）

**方式 3：上位机软件里改**：工程属性/`program.s` 里配置，注意“等号两边不要有空格”。(主手册 p.144、p.150、p.165)

- ⚠️ **上位机模拟器里读 `baud`/`bauds` 永远返回 9600**，实物才准。(主手册 p.769、p.772)

### 4.2 ESP32 侧配置

```c
Serial2.begin(9600, SERIAL_8N1, /*RX=*/16, /*TX=*/17);   // 出厂默认；改过则是新值
```
- 官方 ESP32C3 例程用 `TJC.begin(115200, SERIAL_8N1, RX_Pin, TX_Pin)`，即**8N1**。(主手册 p.337)
- **ESP32 的 3.3V TX → 屏幕 RX 直连**，与屏幕的 3.3V TTL 电平一致；**不需要电平转换，也不需要串 1k 电阻**（串 1k 那条建议是给 X3/X5 的 5V 输出版本用的）。(规格书 p.8 vs. 主手册 p.1444、wiki/debug/connect_mcu)

### 5.4 串口引脚定义 ★

**屏幕端是 XH2.54 4Pin 卧式座子，引脚定义（规格书 p.9，与 p.7 结构图背面丝印一致）：**

| 序号 | 引脚丝印 | 描述 | 接 ESP32 |
|---|---|---|---|
| **1** | **GND** | 电源地 | **GND（必须共地）** |
| **2** | **RX** | 串口接收 | **ESP32 的 TX** |
| **3** | **TX** | 串口发送 | **ESP32 的 RX** |
| **4** | **5V** | 5V 电源输入 | 外部 5V（不是 3.3V） |

- **TX/RX 必须交叉**：“串口屏的 TX（发送）接单片机的 RX（接收），串口屏的 RX（接收）接单片机的 TX（发送），GND 共地”。(主手册 p.193、p.1310、wiki/debug/connect_mcu)
- **必须共地**，否则通讯失败。(主手册 p.193)
- 屏幕 5V 与 MCU 的 5V **不必**连在一起，但 **GND 必须连**。(wiki/debug/connect_mcu 说明3)
- ⚠️ 若手头的板子是 FPC 1.0×14 版本（T1 的 FPC 版本），定义不同：1/2=GND，**6=UART_RXD、7=UART_TXD、13/14=VDD(3.3V)**，12=BEEP（部分 T1 支持）。(主手册 p.93–p.94)
  → **你的是 `_011`（非 `_011F`），按 4Pin XH2.54 走。**
- ⚠️ UART 只能一对一，**不要一条串口挂多个设备**。(主手册 p.195)

## 6. 控件变量模型

### 6.1 命名规则

**格式：`[前缀][序号]`，前缀代表控件类型，序号从 0 开始。**

官方“常用英语”表（主手册 p.1344）解释的是**属性**缩写，而控件前缀是**上位机新建控件时自动生成的**：

| 前缀 | 控件类型（官方常用前缀） | `type` 值 |
|---|---|---|
| **t** | 文本控件（text） | 116 |
| **n** | 数字控件（number） | 54 |
| **b** | 按钮（button） | 98 |
| **bt** | 双态按钮 | 53 |
| **j** | 进度条 | 106 |
| **s** | 曲线波形控件 | 0 |
| **h** | 滑块 | 1 |
| **va** | 变量控件 | 52 |
| **m** | 触摸热区 | 109 |
| **x** | 滚动/滑动文本等 | 55 / 62 |
| **z** | 数字控件（旧式写法，与 n 等价） | 54 |
| **p** | 图片控件 | 112 |
| **data** | 数据记录控件 | 66 |

（`type` 值来自主手册 p.392“控件 ID 对照表”；前缀示例来自主手册 p.389/p.480/p.623/p.876/p.863）
> ⚠️ **【说明】**：手册的控件 ID 对照表给的是 **`type` 数值**（可在屏幕脚本里 `if(...type...)` 判断），**不是** `t0/n0` 里那个数字。`t0` 的“0”只是同类型控件的顺序编号。
> **【需实测确认】**：前缀与类型的一一映射没有一张官方完整表格；以上是按手册中出现的例子归纳。**建议以你上位机工程里实际生成的控件名为准**（新建控件时软件自动命名）。

### 6.2 控件 ID vs 控件名（★上行解析关键）

- 每个页面**最多 250 个控件**，占 **ID 1–250**；**页面控件（页面本身）ID 固定为 0**，名字与页面同名。(主手册 p.390、p.393)
- **控件 ID 由软件自动分配，不可手动设置**；放控件的顺序决定 ID，用“置顶/置底”会改 ID。(主手册 p.876)
- `0x65` 触摸事件回的是 **控件 ID**，不是控件名。(主手册 p.901)
- **名称组（数组）写法：`p[页面ID].b[控件ID].属性`** —— 这里的 `p` 是 page，**`b` 是 object，不是 button**。(主手册 p.869)
  ```
  p0.b[3].val=100
  p[1].b[sys0].txt="abc"
  ```
- `objname`（控件名称）**运行时不可读、不可写，只能在上位机改**。(主手册 p.390、p.480、p.228)

### 6.3 跨页面 / 全局

- 若要 MCU 直接写 `main.t0.txt=...`，**该控件的 `vscope` 属性必须设为“全局”**（默认私有）。(主手册 p.851、p.853)
- ⚠️ 官方强烈建议 MCU **只操作全局变量**，而不是只写 `t0.txt=...`，能避免大量问题。(主手册 p.225、p.878)
- 私有控件在跳页后内存被回收，回来会恢复初始值；**想保持状态要设全局**。(主手册 p.390、p.1345)
- `click` / `vis` / `tsw` **不能跨页面**；定时器只在当前页面跑；曲线只能当前页加数据。(主手册 p.853)

### 6.4 系统变量

| 变量 | 含义 | 范围/默认 | 来源 |
|---|---|---|---|
| **`sys0` `sys1` `sys2`** | 建工程时默认提供的全局整型变量 | int32 | 主手册 p.745 |
| `dp` | 当前页面 ID，可读可写（`dp=2` 即跳页） | — | 主手册 p.576、p.747 |
| `dim` / `dims` | 当前亮度 / 默认亮度 | 0–100 | p.758、p.763 |
| `baud` / `bauds` | 当前波特率 / 默认波特率 | 见 §4 | p.769、p.772 |
| `bkcmd` | 指令执行状态返回控制 | 0/1/2/3，**上电默认 2** | p.789 |
| `recmod` | 串口数据解析模式（0=被动，1=主动解析） | 上电默认 0 | p.949 |
| `usize` | 串口缓冲区当前数据字节数 | 0–1023（T1） | p.950、p.1430 |

### 6.5 全局变量 `va0..vaN` ★

**重要澄清**：**`va0` 不是一个叫“全局变量”的系统变量——`va` 是「变量控件」（Variable 控件）的命名前缀。**(主手册 p.479、p.172)

- **变量控件**：`sta` 设为“数值”就是一个看不见的数字控件；设为“字符串”就是一个看不见的文本控件（可当字符串变量用）。**这是屏幕里唯一能存字符串的变量机制**。(主手册 p.479、p.172)
- 用法：
  ```
  va0.val=123          // 数值型（sta=数值）
  va0.txt="abc"        // 字符串型（sta=字符串）
  va2.txt="<font b="+va0.txt+">"+t0.txt
  ```
  （主手册 p.516）
- **配合 `vscope=全局` 就能跨页面读写**，这就是“全局变量”的推荐做法。(主手册 p.875：“将所有变量控件设置为全局，这样才能跨页面访问”)
- **名称组批量操作**（等价数组）(主手册 p.875)：
  ```
  // 把 va0~va19 批量填 100，前提是它们的 id 号连续
  for(sys0=n0.id;sys0<=n19.id;sys0++)
  {
      page0.b[sys0].val=100
  }
  ```
- **program.s 里的 `int` 才是真·全局整型**：
  ```
  int sys0=0,sys1=0,sys2=0    // 必须写在最前面，只能 int
  ```
  - **只能 int（4 字节有符号，-2147483648~2147483647）**，不能定义 char/float/double/字符串。(主手册 p.172、p.1311)
  - 使用差异：`int sys0` 直接 `sys0=0`；控件（数值/变量控件）必须写 `n0.val=0` / `va0.val=0`。(主手册 p.172)
- **总容量**：
  - 每个页面 ≤ 250 个控件 → 每页最多 250 个变量控件。(主手册 p.390)
  - **运行内存仅 3584 字节**（所有页面 + 全局控件共享）(规格书 p.13) → **`va` 变量不要开太多，尤其字符串型**。(规格书 p.13、p.480 `txt_maxl` 是“分配内存空间”)
  - **【需实测确认】**：`vaN` 能用到多少号、字符串型单个最大长度，官方未给出明确上限，取决于 `txt_maxl` 和剩余内存。

## 7. 中文与特殊字符

### 7.1 编码要求（★）

**必须与上位机工程的“字符编码”设置一致**，两者三选一：

| 工程编码 | MCU 侧编码 |
|---|---|
| **GB2312**（默认，兼容 GBK） | Python: `.encode("GB2312")` 或 `.encode("gbk")`；ESP32-IDF: 需自带 GBK 字模表 |
| **UTF-8** | ESP32/Arduino 原生支持：`.begin(..., UTF8)` 或直接 `TJC.print("中文")` |

来源：(主手册 p.372：“编码应与工程的编码一致（设备-字符编码，如果 usarthmi 中设置的为 utf-8，则这里也填写 utf8，如果 usarthmi 中设置的为 GB2312，则这里也填写 GB2312 也可以填写 GBK）")

**★ Arduino/ESP32 专项结论（对你的项目最重要）**：
> **arduino 只支持 utf8 编码，因此需要发送汉字时，在新建串口屏工程时请选择 UTF8 编码，导入字库时也要使用 UTF8 字库。**
> （主手册 p.337；另见 p.1437“arduino 发送中文时乱码”）

→ **【强烈建议】新建工程时就把字符编码选 UTF-8，字库也导 UTF-8 字库。** 否则 ESP32 侧要额外做 GBK 编码转换。
（主手册 p.1513：“字符编码需要与单片机的字符编码一致”）

- 字库支持 ASCII、GB2312、UTF8 等。(规格书 p.12)
- ⚠️ **中途改工程编码会导致乱码**，中文必须在新工程里**手动重新输入**，不能直接复制。(主手册 p.1424)
- ⚠️ UTF-8 字库体积大，占 FLASH；本型号 FLASH 只有 4MB。(主手册 p.1424、规格书 p.13)
- ⚠️ 系统键盘的汉字输入**只支持 GB2312 编码**；UTF-8 下要汉字输入得用自定义键盘，且“只建议 x 系列使用”。(主手册 p.940、p.944) → **T1 系列 + UTF-8 + 需要屏幕键盘输中文 = 不可行**。

### 7.2 中文指令示例（UTF-8 工程）

ASCII 明文（文件内容）：`main.t0.txt="淘晶驰"`

ESP32 实际发送字节：
```
6D 61 69 6E 2E 74 30 2E 74 78 74 3D 22
E6 B7 98 E6 99 B6 E9 A9 B0      ← "淘晶驰" 的 UTF-8 编码（9 字节）
22 FF FF FF
```
若工程是 GB2312 编码，则中文字节为：`CC D4 BE A7 B3 DB`（"淘晶驰" GB2312，6 字节）。

ASCII 指令原文（主手册 p.225）：
```c
printf("main.t0.txt=\"淘晶驰\"\xff\xff\xff");
```

### 7.3 双引号 / 转义字符

**屏幕侧转义规则（主手册 p.896–p.898、p.1326）：**

| 字符 | 屏幕侧写法 | 说明 |
|---|---|---|
| **双引号 `"`** | **`\"`** | 只有双引号需要转义 |
| 单引号 `'` | 直接写 `'` | **不需要转义** |
| 回车换行 | **`\r`** | **屏幕上的回车换行就是 `\r`，不要用 `\n` 或 `\r\n`** |
| 反斜杠 | 文档在 p.896/p.898 出现 `\\`（“反斜杠：\\”），但 p.1326 又把 `\\` 列在“不支持的转义字符”里 | ⚠️ **矛盾，见 §9 实测清单** |

**示例（主手册 p.896、p.1326）：**
```
t0.txt="hello\rworld"      // 换行
t0.txt="hello\"world"      // 字符串里带双引号 → 显示 hello"world
```

**带双引号的中文文本**（想让屏幕显示 `他说"你好"`）：
```
main.t0.txt="他说\"你好\""
```
ESP32 侧拼串（C 语言要二次转义）：
```c
// 目标屏幕指令: main.t0.txt="他说\"你好\""
printf("main.t0.txt=\"他说\\\"你好\\\"\"\xff\xff\xff");
```

**若要在字符串里输出 0xFF 本身，用 `printh`**（主手册 p.589）：
```
printh ff ff ff
```

**⚠️ 不支持的转义字符**（主手册 p.1326）：
`\?` `\'` `\\` `\a` `\b` `\f` `\n` `\t` `\v` `\ddd` `\xdd`

**想要 0x0D / 0x0A 单字节，必须用 `printh`**（主手册 p.1326）：
```
printh 0d        // 只输出 0x0D
printh 0a        // 只输出 0x0A
printh 0d 0a     // 输出 0D 0A
```
注意：`prints` 输出 `\r` 时**实际会发 0x0D 0x0A 两个字节**。(主手册 p.1326)

## 8. 常见坑

### 8.1 开机握手 ★

- **设备上电初始化成功后会发 `0x88 + FF FF FF`（`88 FF FF FF`）**。(主手册 p.909)
- ⚠️ **1.65.0 版本以前**：固定自动发送；
  **1.65.0 版本以后**：**取消固定发送**，改为由 `Program.s` 里的代码发送（用户可自行注释/删除）。(主手册 p.909)
  → **【需实测确认】**：你的屏固件版本是多少、上电到底发不发 `88 FF FF FF`。
- **官方 ESP32 例程的稳妥做法（推荐照抄）**（主手册 p.337）：
  ```c
  TJC.begin(115200, SERIAL_8N1, RX_Pin, TX_Pin);
  // 因为串口屏开机会发送 88 ff ff ff，所以要清空串口缓冲区
  while (TJC.read() >= 0);
  TJC.print("page main\xff\xff\xff");
  ```

### 8.2 上电延时 ★

- 主控与屏同时上电时，主控可能先初始化完，此时发指令会**丢失**。(主手册 p.1316)
- **官方建议延时**：**T0/K0 系列 250ms；X3/X5 系列 1.5s**。(主手册 p.1316)
- **T1 系列没有单独给出数值** → **【需实测确认】**，建议 **≥300ms**（T1 是 64MHz M0，比 X 系列慢），或改为**等 `88 FF FF FF`**（拿不到就超时放行）。**【推断】**

### 8.3 上电第一条指令前先发 `0x00 FF FF FF`

某些 MCU 上电时会翻转串口 IO 电平，导致屏幕收到杂波、第一条指令解析失败。官方做法（主手册 p.1317）：
```c
printf("\x00\xff\xff\xff");     // 发一次空指令，终结缓冲里的杂波
```
- 原理：这条带 3 个 0xFF 结束符，会被解析，并**顺带清空屏幕串口缓冲区里的无关数据**。(主手册 p.1317)
- 也可以“第一次发指令时发两条一样的”，第一条充当清缓冲。(主手册 p.1317)
- **【推断】** 这在 ESP32 上通常不必要（ESP32 串口引脚上电态稳定），但如果出现“第一条指令总失败”，照这个加。

### 8.4 指令太长 → 分段 ★

- **T1 串口缓冲区只有 1024 字节**；长文本会在收满一半时缓冲区就满，**根本收不到结束符 `FF FF FF`**，导致整条指令作废。(主手册 p.1430、规格书 p.13)
- **官方解法：用 `+=` 分多条拼接**（主手册 p.1430）：
  ```
  t0.txt="第一段....."\xff\xff\xff
  t0.txt+="第二段....."\xff\xff\xff
  t0.txt+="第三段....."\xff\xff\xff
  ```
- **另两个限制**：
  - `txt_maxl`（控件字符最大长度 / 分配内存）不够 → 显示不全。(主手册 p.1425、p.480)
  - **变量名最长 29 字符**，超出返回 `23 FF FF FF`。(主手册 p.899)
- **建议**：单条指令文本控制在 **≤900 字节**以内。**【推断】**（缓冲区 1024B，留余量）

### 8.5 连续快速发指令会丢吗？ ★

**会。** 官方明确（主手册 p.900）：
> “1. 发送的速度太快了，**建议每条指令间隔 100 毫秒**；2. 发送了太多无关的指令，串口屏无法进行解析，导致串口缓冲区被占满。”

- 缓冲区满时屏幕返回 **`24 FF FF FF`**；溢出的数据**直接丢弃**，直到队列腾出空间。(主手册 p.900)
- **`24 FF FF FF` 不受 `bkcmd` 影响**，主动解析模式下缓冲区满了也会返回。(主手册 p.900)
- 同一建议在 p.1430 再次强调：“发送数据的间隔，建议是每条指令间隔 100ms，避免发送过快导致屏幕解析不过来从而导致数据丢失。”
- **【推断】实操建议**：ESP32 侧每发一条指令后 `delay(100)` 或**等待 `01 FF FF FF`（`bkcmd=1` 时）** 再发下一条；纯 UI 批量刷新时用 `ref_stop` … `ref_star` 包起来减少刷新开销。(ref_stop 见 p.704)
- **【需实测确认】**：实测本屏在 115200 下的**最小安全间隔**（100ms 很可能过于保守，但官方只给了这个数）。

### 8.6 `sendme` 怎么用

```
sendme
```
- 屏幕**立即**把当前页面 ID 发到串口，格式：`66 <页面ID> FF FF FF`。(主手册 p.695、p.902)
- 想每次刷新页面自动发：写在该页面的**初始化事件**里。(主手册 p.695)
- ⚠️ **官方不建议用 `sendme`**：“因为 `sendme` 指令发出的数据格式是固定的，可能和你原有的格式不符”。(主手册 p.695)
- **推荐替代写法**（可完全自定义帧头帧尾）(主手册 p.695)：
  ```
  printh 66
  prints dp,1
  printh ff ff ff
  ```

| 坑 | 说明 | 来源 |
|---|---|---|

## 10. ESP32 最小可用骨架（可直接编译）

```c
// ESP32 → TJC3224T124_011  最小骨架
// 接线: ESP32 GPIO17(TX) → 屏 RX(2脚) | ESP32 GPIO16(RX) → 屏 TX(3脚) | GND ↔ 屏 GND(1脚)
//       屏 5V(4脚) ← 外部 5V 1A（不要用 3.3V！）
#include <Arduino.h>

#define TJC_BAUD   9600          // 出厂默认；若工程里写了 bauds=115200 就改成 115200
#define TJC_RX_PIN 16            // ESP32 的 RX ← 接屏的 TX
#define TJC_TX_PIN 17            // ESP32 的 TX → 接屏的 RX
#define TJC Serial2

static inline void tjc(const char *cmd) {
    TJC.print(cmd);
    TJC.write(0xFF); TJC.write(0xFF); TJC.write(0xFF);   // 固定 3 字节结束符
    delay(100);                                          // 官方建议间隔 100ms
}

void setup() {
    TJC.begin(TJC_BAUD, SERIAL_8N1, TJC_RX_PIN, TJC_TX_PIN);
    delay(300);                       // T1 上电启动留时间（官方未给 T1 数值，见 §8.2）
    TJC.write(0x00); TJC.write(0xFF); TJC.write(0xFF); TJC.write(0xFF);  // 清杂波(可选)
    while (TJC.read() >= 0);          // 清空开机残留(如 88 FF FF FF)

    tjc("page main");                 // 切页
    tjc("main.t0.txt=\"Hello\"");     // 文本（控件须设为全局）
    tjc("main.n0.val=123");           // 数值
}

void loop() {
    // 解析 0x65 触摸事件： 65 <pid> <cid> <evt> FF FF FF
    if (TJC.available() >= 7) {
        if (TJC.peek() == 0x65) {
            uint8_t b[7];
            TJC.readBytes(b, 7);
            if (b[4] == 0xFF && b[5] == 0xFF && b[6] == 0xFF) {
                uint8_t page = b[1], ctrl = b[2], evt = b[3];  // evt: 0x01=按下 0x00=弹起
                (void)page; (void)ctrl; (void)evt;
                if (evt == 0x01) { /* 按下处理 */ }
            }
        } else {
            TJC.read();               // 跳过非帧头字节
        }
    }
}
```
说明：串口接收解析建议按官方建议**在中断里灌进 1KB 环形缓冲区，主循环里解析**。(wiki/debug/base/tjc2mcu 说明5)
