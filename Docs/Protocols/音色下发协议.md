## 0. 一句话

音色参数表（`inc/env0/rate/aatk` 共 2016 个字）原先靠 `$readmemh` **在综合时**烧进 BSRAM，
现在给这块 BSRAM 加了一个**同步写端口**：ESP32 用 `0x09 TONEWR` 一条 11 字节的帧写一个字，
逐条把整套音色灌进去，**不用重新综合/烧板就能换音色**。

```
串口屏 ──UART──► ESP32 ──UART 115200──► FPGA top_gv_host
                                                 │ 0x09 TONEWR 解析（ESP32 段）
                                                 ▼
                                          additive4_tone u_eng ──► tone_rom u_rom
                                                 │                      │
                                                 │            mem_inc/mem_env0/mem_rate/mem_aatk
                                                 │            （4 块可写 BSRAM，上电初值仍是 *.hex）
                                                 ▼
                                    加法合成引擎读同一组地址 → 发声
```

> ⚠ **别混了两套帧**：`docs/UART帧协议规范.md` 写的是**计划中**的另一套协议
> （`AA 55 | LEN | TYPE | SEQ | PAYLOAD | CRC8`、1 Mbps）。**当前 RTL 里实际跑的是本文这套**
> —— `AA | CMD | LEN | PAYLOAD | CRC`、115200、CRC = 异或和，实现在
> `top_gv_host.v` 的"★ ESP32 链路（串口屏的中间桥）"段。

## 1. 帧格式（与 0x06/0x07/0x08 完全一致）

```text
下行（屏幕/PC → FPGA）
┌──────┬──────┬──────┬─────────────────────┬──────┐
│ 0xAA │ CMD  │ LEN  │      PAYLOAD        │ CRC  │
│ 1B   │ 1B   │ 1B   │      LEN 字节        │ 1B   │
└──────┴──────┴──────┴─────────────────────┴──────┘
  CRC = CMD ^ LEN ^ PAYLOAD[0] ^ ... ^ PAYLOAD[LEN-1]      （逐字节异或）
```

| CMD | 名称 | 载荷 | 说明 |
| --- | --- | --- | --- |
| `0x06` | GAIN | `[vol]` | 音量 0..255 |
| `0x07` | TIMBRE | `[idx]` | 音色索引 0..3，**只记录**（见 §6） |
| `0x08` | OPTOCFG | `[ch, th_lo, th_hi, gain]` | 光电阈值/增益 |
| **`0x09`** | **TONEWR** | **`[sel, addr_lo, addr_hi, d0, d1, d2, d3]`** | **★ 本文：音色数据写入（BSRAM）** |

上行状态帧（50 ms 一次，与本文无关但一并列出，用于屏幕回显）：
`AA | 0x81 | 0x04 | [音库号, 音量, 音色索引, flags] | CRC`

### 1.1 `0x09 TONEWR` 字段（字节级）

**`LEN = 7`**（⚠ 需求文档写的是"载荷 8 字节"，但列出的字段只有 7 个；
固件按 `LEN ≥ 7` 接收，**多出来的字节只参与 CRC、不被使用**，所以两种写法都能兼容）：

| 序号 | 字段 | 位宽 | 含义 |
| --- | --- | --- | --- |
| `payload[0]` | `sel` | 2 bit | `0`=inc `1`=env0 `2`=rate `3`=aatk（高位保留，固件只看低 2 位） |
| `payload[1]` | `addr_lo` | 8 bit | 地址低 8 位 |
| `payload[2]` | `addr_hi` | 8 bit | 地址高位，**只用 bit0**（= 地址 bit8）；bit7..1 忽略 |
| `payload[3]` | `d0` | 8 bit | 数据字节 0（**小端最低字节**） |
| `payload[4]` | `d1` | 8 bit | 数据字节 1 |
| `payload[5]` | `d2` | 8 bit | 数据字节 2 |
| `payload[6]` | `d3` | 8 bit | 数据字节 3（**小端最高字节**） |

- `addr = {payload[2][0], payload[1]}`，范围 **0..511**（数组深度 512，见 §2）。
- `data = {payload[6], payload[5], payload[4], payload[3]}`（小端 32 位）。
- 各数组取位宽度（**超出的高位在 RTL 里被截掉，不报错**）：

| `sel` | 数组 | 位宽 | 实际写入 |
| --- | --- | --- | --- |
| 0 | `mem_inc` | 32 bit | `data[31:0]`（四个字节全用） |
| 1 | `mem_env0` | 16 bit | `data[15:0]`（用 `d0/d1`） |
| 2 | `mem_rate` | 12 bit | `data[11:0]`（用 `d0` 全部 + `d1` 低 4 位） |
| 3 | `mem_aatk` | 16 bit | `data[15:0]`（用 `d0/d1`） |

- 长度不足 7 的 `0x09` 帧**执行"不写"**（防半截帧改坏音色表），但仍计入 `es_ok_cnt`。
- CRC 不通过 ⇒ **什么都不做**（与其它 CMD 一样，直接回 `ES_SYNC` 等下一帧同步头）。

### 1.2 帧例子（可直接用串口助手发）

| 动作 | 帧（十六进制，空格分隔） |
| --- | --- |
| 写 `inc[0] = 0x015F25DC` | `AA 09 07 00 00 00 DC 25 5F 01 A9` |
| 写 `env0[0] = 0x101B` | `AA 09 07 01 00 00 1B 10 00 00 04` |
| 写 `rate[0] = 0x041` | `AA 09 07 02 00 00 41 00 00 00 4D` |
| 写 `aatk[0] = 0x089E` | `AA 09 07 03 00 00 9E 08 00 00 9B` |
| 写 `inc[503] = 0x00010203` | `AA 09 07 00 F7 01 03 02 01 00 F8` |

（以上帧的 CRC 由 `fw_scripts` 里的公式重算核对过；生成器见 §7。）

## 2. 地址映射（写哪儿 = 改哪个音色参数）

`tone_rom.v` 的四张表与 `src/fpga_mem/*.hex` **一一对应**，地址含义完全相同：

```
addr = 音库号 × PT_N + 泛音槽号
        PT_N = 18（每音 18 个泛音槽，见 src/tone_rom_params.vh / work/gen_tone_rom_hex.py）
        音库号 0..27（BANK_REC28：音库号 = MIDI − 60，C4..D#6）
        泛音槽 0..17
⇒ 实际用到的地址 = 28 × 18 = 504 个（0..503），504..511 是补零区（写它没意义）
```

> ★ **v62 更新**：`PT_N`（步长 K）**已经不再是编译期常量**了 —— 引擎改成用运行时端口
> `pt_k`（rec28=18 / guitar33=15），见 `音色库步长切换.md`（历史路径：`音色库步长切换.md`）。
> 本文上面的地址映射仍是**写入侧**的约定（写哪个地址就是改哪一格），它没变；
> 但"一个音占几格"现在取决于屏幕当前选的是哪套音色：
> rec28 → `addr = 音库号×18 + 泛音槽`（0..503）、guitar33 → `addr = 音库号×15 + 泛音槽`（0..494）。
> ESP32 的 `downloadTimbre` 会**先发 `0x07 TIMBRE`**（决定 pt_k）再灌数据，顺序不能反。

| 数组 | 每槽含义（引擎里的用法，见 `additive4_tone.v`） |
| --- | --- |
| `inc` | 相位增量 `f·2^32/Fs`（32 bit，决定音高；滑音时再乘 `pitch_mul`） |
| `env0` | 包络初值 `amp<<9`（16 bit 有效，25 bit 内部） |
| `rate` | 包络衰减步长（12 bit，每采样 `env -= (env·rate)>>22`） |
| `aatk` | 起振支参数（16 bit，双指数包络的"从 0 升到峰"那条支路） |

- 一套完整音色 = 504 地址 × 4 数组 = **2016 个字** = 2016 条 `0x09` 帧 = **22176 字节**
  （@115200 8N1 ≈ 11520 B/s ⇒ **约 1.9 s**，见 §7.2）。
- 四个数组**必须一起写**才算换了音色：只写 `inc` 会变调但包络还是老的。

## 3. 写时序（RTL 层面）

### 3.1 一帧的生命周期

```text
ESP32 送：  AA   09   07   00  00  00   DC  25  5F  01   A9
            ①    ②    ③    ④   ⑤   ⑥   ⑦   ⑧   ⑨   ⑩   ⑪    （11 字节 ≈ 0.95 ms @115200）
                                       └─── payload ───┘   └CRC┘

FPGA top_gv_host.v 的 ESP32 段（es_st 状态机）：
  uart_rx 每收完一个字节 → esp_rx_valid 拉高 1 拍
  ES_SYNC → ES_CMD → ES_LEN → ES_DATA×7 → ES_CRC
  ES_DATA：es_pay[0..7] 依次缓存载荷（v61 由 4 字节扩到 8 字节）
  ES_CRC ：rx_byte == es_crc ? 执行 : 丢弃

  tone_we_r :  ──────────────────────────────┐ 1 拍(20 ns) ┌──────
                                            └────────────┘
  tw_sel/tw_addr/tw_data（组合自 es_pay，CRC 拍之后仍然有效）
  ↓
  additive4_tone u_eng → tone_rom u_rom 的写端口
  ↓
  always @(posedge clk)  :  若 we 且 sel==k ⇒ mem_k[waddr] <= 数据
```

- 写是**同步写**（`posedge clk`），**不跨时钟域**（ESP32 链路、引擎、BSRAM 全在 `clk_50m`）。
- `tone_we` 只在 CRC 通过后拉高 **1 拍**；数据/地址来自 `es_pay` 寄存器，稳态。
  不要改成"直接用 `esp_rx_byte` 组合驱动写端口"——那样地址/数据会在字节流中抖动。

### 3.2 与"引擎每拍都读 BSRAM"如何共存（关键设计）

引擎的槽流水**每个 clk 都在读** `tone_rom`（`rom_addr = 音库号×18 + 泛音槽`，4 拍/槽）。
写入随时可能落在这条读流的任意一拍上，所以写端口必须是**写穿透（write-through）**语义：

```verilog
// tone_rom.v（v61）
wire hit_inc = we && (wsel == 2'd0) && (waddr == addr);   // 同拍、同址、同数组
always @(posedge clk) begin
    if (we) mem_inc[waddr] <= wdata;                      // ① 同步写
    inc <= hit_inc ? wdata[31:0] : mem_inc[addr];         // ② 读（每拍都读），命中则直通写数据
end
```

| 情形 | 行为 |
| --- | --- |
| 写 A 格、同一拍读 B 格（绝大多数） | 正常读出 B 格；A 格在下一拍起是新值 |
| 写 A 格、同一拍正好读 A 格（写穿透命中） | 该拍输出**直接用写数据**（写优先），不读旧值 |
| 写的那一拍**读输出会不会被憋住** | **不会**——读永远是"读"，只是命中的那一格换成新值 |

- **生效时间**：写命中的那一格**同一 clk 沿**就生效；正在发声的音其参数在"下一次轮到该槽"
  时更新（一个采样窗口 = 1024 clk ≈ 20.5 µs 内）。所以"边响边写"会听到音色**渐变**；
  要做到"咔"一下换干净，请在**静音时**下发整套音色（见 §7.2）。
- 写操作只占 1 拍，**不影响** `sample_tick` 节拍、I²S 时序、槽流水预算
  （12 声部 × 18 槽 × 4 拍 + 13 = 877 ≤ 1024 拍/采样，一线未动）。

## 4. 综合器的坑：PA2122 / 写模式 / 初值（**改这块代码前必读**）

### 4.1 PA2122：GW5A 的 BSRAM 不支持"读旧值"

综合器一旦把某个"看着像 RAM"的结构推成 `WRITE_MODE = 2'b10`（READ_BEFORE_WRITE），
整个工程**直接失败**——这个工程已经在 `touch_recog.v` 的 `pipe` 移位寄存器上栽过一次：

```text
ERROR (PA2122) : Not support 'pipe_pipe_0_0_s'(SP) WRITE_MODE = 2'b10,
                 please change write mode WRITE_MODE = 2'b00 or 2'b01.
```

`tone_rom.v` 的写法就是为了**绕开这个模式**，三条铁律：

| 写法 | 综合出的写模式 | 能不能用 |
| --- | --- | --- |
| `if (we) mem[w]<=d;  dout<=mem[a];`（读不加判断 = 读旧值） | `2'b10` read-before-write | ❌ **PA2122，整个工程失败** |
| `if (we) mem[w]<=d; else dout<=mem[a];`（写的那拍不读） | `2'b00` normal-write | ⚠ 能过，但**写的那一拍读输出被憋住**，引擎那一槽会拿到上一槽的参数 → 咔哒声 |
| **`if (we) mem[w]<=d;` + `dout <= hit ? d : mem[a];`（写穿透 + bypass）** | `2'b01` write-through | ✅ **本版采用，构建通过** |

> 另外：**写和读必须在同一个 `always` 块里**。分成两个 `always`（一个写、一个读）时，
> 有的版本会退化成 FF 阵列（512×76 = 3.9 万个寄存器，直接爆资源）。

### 4.2 另一个真实踩到的坑：**声明顺序（EX1998）**

`0x09` 的解析在 `top_gv_host.v` 文件后部（ESP32 段），而 `u_eng`/`tone_rom` 的例化在文件中间。
第一版把 `tw_sel / tw_addr / tw_data` **声明在使用之后**，综合器把它们当成"使用处的隐式网线"：

```text
WARN (EX1998) : Net 'tw_sel[1]'  does not have a driver
WARN (EX1998) : Net 'tw_addr[8]' does not have a driver
WARN (EX1998) : Net 'tw_data[31]' does not have a driver
```

后果**不只是告警**：`wsel` 最高位恒 0 ⇒ 综合器证明 `sel=2/3`（rate/aatk）的写分支**永远不成立**，
于是把那两个数组又折叠回"只读 ROM"：

| 构建 | u_rom 的 BSRAM | 全设计 pROM | 结论 |
| --- | --- | --- | --- |
| 修正前（build_gv15） | 3 块 = **1 SDPB + 2 pROM**（`u_eng` 自己的 3 个数组已占 3 块 SDPB，全设计 4 SDPB，故 `u_rom` 3 块里有 2 块是 pROM） | 2 | rate/aatk **写不进去**（静默失效！） |
| **修正后（build_gv16）** | **4 块，全是 SDPB**（一数组一块） | **0** | 四个数组都能写 ✅ |

⇒ 排查方法：`impl/gwsynthesis/gv_host_syn_rsc.xml` 里 `<SubModule name="u_rom" Bsram="4">`
且 `gv_host_syn.rpt.html` 的 BSRAM 明细里 **`pROM = 0`**。

### 4.3 `$readmemh` 的初值有没有被优化掉

BSRAM 的上电初值**只能**靠 `initial`/`$readmemh` 写进 BSRAM 的 INIT 位，所以 `tone_rom.v`
的 `initial` 段**一字未改**（先清零，再 `$readmemh` 四张表，绝对路径照旧）。本次构建的核查：

| 检查项 | 结果 |
| --- | --- |
| 综合日志是否有 `Extracting RAM for identifier 'mem_inc'/'mem_env0'/'mem_rate'/'mem_aatk'` | ✅ 四条都在（`src/tone_rom.v:73-76`） |
| 是否出现"initial value 被忽略/丢弃"类告警 | ✅ 没有。`build_gv16.log` 的告警只有既有的 `EX3209`（`touch_tables.vh` 宏）/`EX3791`·`EX3792`（位宽截断）/`CV0016`，**`EX1998` 已消失**，且没有任何 initial/readmemh 相关告警 |
| 四个数组是否仍映射进 BSRAM | ✅ `u_rom` = 4 块 BSRAM（`gv_host_syn_rsc.xml`） |
| 是否还有"被当 ROM 折叠"的数组 | ✅ 全设计 `pROM = 0`（修正后） |

## 6. `0x07 TIMBRE` 目前的角色（预留接口）

- `top_gv_host.v` 里 `0x07` 只做一件事：把索引记进 `esp_timbre`（0..3），
  并在 50 ms 的上行状态帧里回显给屏幕（帧第 6 字节 = 载荷第 3 字节，屏幕用来自绘"当前音色"）。
- **目前只有一套物理音色数据**，所以 `esp_timbre` 还不参与寻址，接口这样留：
  将来加第二套库时把 `tone_rom` 的 `DEPTH` 从 512 扩到 1024、`addr/waddr` 各加 1 位，
  **最高位接 `esp_timbre[0]`** 当"库选择"（`$readmemh` 再加载一套 `bank1_*.hex` 即可）。
  这个预留点在 `tone_rom.v` 头部注释里也写了一份。
- 换音色的**数据**通路就是本文的 `0x09`；`0x07` 只负责"选哪一套"这个数字。

## 7. ESP32 / PC 侧怎么用

### 7.1 生成一帧（Python，与固件逐字节对齐）

```python
def tonewr_frame(sel: int, addr: int, val: int) -> bytes:
    """sel: 0=inc 1=env0 2=rate 3=aatk; addr: 0..511; val: 该数组的值（32 位内）"""
    pay = [sel & 0x03, addr & 0xFF, (addr >> 8) & 0x01,
           val & 0xFF, (val >> 8) & 0xFF, (val >> 16) & 0xFF, (val >> 24) & 0xFF]
    crc = 0x09 ^ len(pay)
    for b in pay:
        crc ^= b
    return bytes([0xAA, 0x09, len(pay)] + pay + [crc])

# 例：把 inc[0] 写成 0x015F25DC
print(tonewr_frame(0, 0, 0x015F25DC).hex(' '))   # aa 09 07 00 00 00 dc 25 5f 01 a9
```

### 7.2 灌一整套音色（2016 条帧）

| 项 | 数值 |
| --- | --- |
| 帧长 | 11 字节（AA+CMD+LEN+7 载荷+CRC） |
| 帧数 | 504 地址 × 4 数组 = **2016** |
| 总字节 | 22176 B |
| @115200 8N1 | ≈ **1.93 s**（每帧约 0.95 ms） |
| @1 Mbps（若以后改波特率） | ≈ 0.22 s |

建议的固件流程（ESP32）：

1. 屏幕点"音色 N" → ESP32 先发一条"静音"（把 `0x06 GAIN` 发 0，或让引擎自然衰减）；
2. 按 addr = 0..503、sel = 0..3 的顺序连发 2016 条 `0x09`，每条之间**不必**加延时
   （115200 下 UART 本身就是节流；FPGA 每字节处理 1 拍，来得及）；
3. 发 `0x07 TIMBRE = N`（记录索引，供状态帧回显）；
4. 恢复 `0x06 GAIN`；
5. 可选自检：看 50 ms 状态帧是否照常回来（说明 FPGA 没被写崩）。

⚠ 强烈建议**静音时下发**：边响边写会让正在发声的音的 `inc/rate/env0/aatk` 逐条变化
（听感是音高/包络渐变），虽然不会崩，但不干净。

### 7.3 想更快？（未实现，仅备注）

现在是一帧写一个字。若要更快，可以加一条 `0x0A BLKWR`（一帧 `[sel, addr_lo, addr_hi, count, d0..dN]`）
在 FPGA 里配一个自增地址的小状态机。本次**没做**——1.9 s 对本项目可接受，且新命令要同步改 ESP32 固件。
