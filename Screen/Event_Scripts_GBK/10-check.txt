★ 本页**不发任何 AA 0A 帧**。
  固件里没有自检协议（screen_link.cpp / main_app.cpp 里没有 0x20），
  新增它要动 FPGA + ESP32 + 屏三边；而现有数据通路已经够屏自己判定。
  本页只发 `AA 0B` 要实时数据，然后自己数触发次数。零固件改动。

★ 弦序（按屏幕行序，不是 1/2/3/4 弦序）
    步骤 2  G  ← vdg0 / vp0   vev bit0 (值 1)   需要 ≥ 3 次
    步骤 3  C  ← vdg2 / vp2   vev bit2 (值 4)   需要 ≥ 2 次
    步骤 4  E  ← vdg1 / vp1   vev bit1 (值 2)   需要 ≥ 2 次
    步骤 5  A  ← vdg3 / vp3   vev bit3 (值 8)   需要 ≥ 2 次
    结果灯 t_r1~t_r4 依次显示 G / C / E / A

// ===== ③ 触发计数（上升沿 + 去抖 200ms）=====
//
//   vev 是"最近 100ms 内触发过"的【锁存】值，同一根弦可能连续两帧都为 1，
//   直接数"当前为 1"会把一次拨弦数成 2 次，所以必须做上升沿检测。
//
//   vusev=1 → 用 vev 位图判（FPGA 的判定结果，最准）
//             在 Program.s 里改。改 ESP32 加上 vev 后改成 1。

      vthr=vp3

================================================================
  说明
================================================================

1. ★★ 判定在屏侧，不下位机。
   固件没有任何自检命令（核对过 screen_link.cpp 和 main_app.cpp）。
   屏自己数"这 5 秒里这根弦触发了几次"，达到次数就算通过。

2. 自检固定使用实际送入音频的vev事件，超阈值不等于发声。

3. ★ 上升沿检测是必须的。vev / 强度都是 100ms 锁存值，
   一次拨弦会连续 2~3 拍为真，直接数"当前为真"会把一次数成三次。

4. ★ `covx` 是数值转文本的唯一办法。
   `t_cnt.txt="已 "+vcnt` 这种写法编译能过但显示是空的（官方 p.844 明确列为错误）。
   必须先 `covx vcnt,t_tmp.txt,0,0` 转到屏外的 `t_tmp`，再拼字符串。

5. ★ 乘号要写在前面：`16*vst+8*vr3+...`
   TJC 没有运算符优先级，一律左到右。`vr0+2*vr1` 会被算成 `(vr0+2)*vr1`。

6. 步骤 1 会数环境噪声（`vnoise`）。50 拍里有超过 3 拍检测到触发，
   就把副提示改成"环境光偏强"提醒用户，但不阻断流程。

7. 进度条 `j0` 的 `maxval=100`，`vprog=vtk*2` => 50 拍正好走满 100。

8. 本页需要的中文（记得进字库）：
   光电管自检、步骤、请拿好尤克里里、以演奏姿势持琴，静置不动、
   请拨、弦、秒内拨动、到、次、已、环境光偏强、
   准备中、进行中、等待结果、自检成功、自检失败、
   四弦全部正常、可以开始演奏、有弦未通过、请重新拨弦或调灵敏度、
   通过、未过、取消自检、重新自检、返回
